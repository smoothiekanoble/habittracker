Garmin Sleep Sync Research

Local-first spike for importing Garmin Connect sleep into HabitTracker daily_metrics. Authentication is treated as experimental; credentials, token cache, and raw JSON must stay outside git.

Prepared June 11, 2026. Production upsert requires explicit --upsert.

Recommendation

Use python-garminconnect for authentication and token refresh. Fetch sleep with get_sleep_data(date) first, then fall back to the richer known endpoint /gc-api/sleep-service/sleep/dailySleepData?date=YYYY-MM-DD&nonSleepBufferMinutes=60 through the authenticated client if needed.

Run locally with GARMINTOKENS=local-data/garmin/tokens. GitHub Actions can run dry-run experiments, but token persistence there is fragile unless tokens are stored in a secret or cache. Local Windows token cache is preferred.

Library Findings

  • The latest python-garminconnect README says authentication uses Garmin's mobile SSO flow and stores tokens by default under ~/.garminconnect/garmin_tokens.json.
  • login(tokenstore) also honors GARMINTOKENS. When it is a path, the library loads cached tokens from that path, refreshes expiring DI tokens, and dumps refreshed tokens back to the path.
  • The current source defines garmin_connect_daily_sleep_url = "/wellness-service/wellness/dailySleepData". get_sleep_data(cdate) calls that endpoint with date and nonSleepBufferMinutes=60.
  • The known richer endpoint is under /gc-api/sleep-service/sleep/dailySleepData. The spike script attempts the library method first and falls back to that direct endpoint through client.connectapi(...).

Secret and Raw Data Rules

  • Use GARMIN_EMAIL and GARMIN_PASSWORD from environment variables or an untracked local env file.
  • Use GARMINTOKENS=local-data/garmin/tokens.
  • Save raw Garmin JSON only with --save-raw, under local-data/garmin/raw-sleep/YYYY-MM-DD.json.
  • .gitignore already ignores local-data/, .env.local, and .env*.local.

Schema

Garmin uses the existing canonical daily_metrics table established by the MedM integration. The unique daily identity is:

UNIQUE (user_id, metric_date, metric_type, source)

Garmin sleep rows use source = "garmin", with provider and endpoint metadata inside the JSON source_detail field.

Local Test Steps

  1. Install dependencies: pip install garminconnect curl_cffi.
  2. Create an untracked .env.local or set environment variables for GARMIN_EMAIL, GARMIN_PASSWORD, and HABITTRACKER_USER_ID.
  3. Run a dry-run: python scripts/garmin/sync_garmin_sleep.py --date 2026-06-10 --dry-run.
  4. Optionally save raw JSON locally: python scripts/garmin/sync_garmin_sleep.py --date 2026-06-10 --dry-run --save-raw.
  5. Only after reviewing output and confirming the existing metrics migrations are applied, run with --upsert.

GitHub Actions

The workflow is manual workflow_dispatch only. A once-daily schedule is present but commented out. It uses these secrets: GARMIN_EMAIL, GARMIN_PASSWORD, SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, and HABITTRACKER_USER_ID. It dry-runs by default unless the upsert input is set to true.

Actions Auth Risk

Garmin auth may require MFA, rate-limit new environments, or reject repeated fresh logins. Since GitHub-hosted runners are ephemeral, token persistence may not work unless token data is stored as a secret or restored from a cache. Prefer the local Windows token cache for reliable experimentation.
